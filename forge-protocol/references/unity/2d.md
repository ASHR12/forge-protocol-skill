# Unity 2D: the 2D renderer, sprites, atlases, tilemaps, 2D lights, pixel-perfect camera, 2D physics and animation

## The 2D renderer and the Universal 2D template

**Goal.** A sprite game starts on the pipeline and packages that give it 2D lights, shadows and pixel-perfect rendering, with nothing that only works in the Built-in pipeline.

**Build.**
1. Create the project from the Universal 2D template: URP with the 2D Renderer already set up. The copy bundled with 6000.6.4f1 lists 2D Animation, the PSD and Aseprite importers, Sprite, Sprite Shape, Tilemap, Tilemap Extras, 2D Tooling, the Input System, Timeline and uGUI.
2. Keep the camera orthographic for flat 2D. Its size follows from the art: orthographic size is half the vertical resolution divided by Pixels Per Unit.
3. Pick the 2D Renderer's Default Material Type: Lit (`2D/Sprite-Lit-Default`) when the game uses 2D lights, Unlit otherwise.
4. Don't add the separate 2D Pixel Perfect package, which only works with the Built-in pipeline; URP has its own Pixel Perfect Camera (see The pixel-perfect camera).
5. Effects: the Particle System works everywhere; VFX Graph in a 2D project draws 3D particles with sorting layers but no 2D lights or 2D physics, and never runs on WebGL 2 ([effects.md](effects.md)).

**Watch for.** The 2D feature set in the Package Manager installs the Built-in-only Pixel Perfect package along with the rest; remove it again. 2D lights don't exist outside the 2D Renderer.

**API facts** (check the installed version):
- 2D Lights and 2D Shadows exist only in URP with the 2D Renderer (verified on 6000.6).
- The Universal 2D template is a URP project preconfigured with the 2D Renderer, and it includes the URP Pixel Perfect Camera; the separate 2D Pixel Perfect package works only with the Built-in pipeline (verified on 6000.6).
- In URP's 2D Renderer, VFX Graph supports 3D particles, sorting layers and sprite-lit Shader Graph targets, but not 2D physics, 2D sprite emitters or 2D lights (verified on 6000.6).

## Sprite import

**Goal.** Every sprite keeps its art at the intended size and crispness, and all of them share one pixel density.

**Build.**
1. Import art as Texture Type Sprite (2D and UI), Sprite Mode Single, or Multiple for sheets sliced in the Sprite Editor.
2. Choose one Pixels Per Unit for the whole game, matching the tile size (a 16-pixel tile at 16 PPU is one unit), and use it for characters, tiles and props alike.
3. Pixel art: Filter Mode Point, Compression None, and custom pivots in pixel units, so pivots snap to pixels. Painted art: Bilinear filtering and compression chosen per target ([assets-and-import.md](assets-and-import.md)).
4. Use Mesh Type Tight to cut transparent overdraw on large sprites, with the Delaunay Subdivision triangulation (new in 6.6) for a closer fit; keep Full Rect for tiles.
5. Generate a physics shape from the sprite's outline where colliders follow it.
6. Bring layered characters in through the PSD Importer (`.psb`) or the Aseprite Importer, which keep layers and animation frames.

**Watch for.** Mixed Pixels Per Unit makes pixels different sizes on screen. Bilinear filtering or compression on pixel art blurs edges and shifts colors.

**Critic checks.** PASS when every sprite on screen shows the same pixel size, edges are clean at native size, and no halos or bleeding lines surround sprites. FAIL signs: some sprites chunkier than others; soft, blurry pixel art; colored fringes at sprite edges.

**API facts** (check the installed version):
- Mesh Type is Full Rect or Tight, and sprites smaller than 32 × 32 pixels always use Full Rect (verified on 6000.6).
- Tight meshes can use the Delaunay Subdivision triangulation, which fits the outline more closely at the cost of more vertices (verified on 6000.6).

## Sprite Atlas

**Goal.** Sprites batch into few draw calls, and no sprite picks up pixels from its neighbors.

**Build.**
1. Create an atlas with Assets > Create > 2D > Sprite Atlas, and add folders or sprites under Objects for Packing.
2. Group sprites that draw together (one level's tiles, one character, the HUD) into one atlas each, and put each sprite in exactly one atlas.
3. Keep Padding at least at its default for pixel art, turn Allow Rotation off for UI, and use Tight Packing for irregular shapes.
4. Match the atlas's own Filter Mode and compression to the sprites, since the atlas texture is what draws.
5. Check the result with Pack Preview, and keep Include in Build on unless you load atlases yourself.

**Watch for.** A sprite in two atlases is drawn from either one at random at runtime. Read/Write on atlas textures costs memory; leave it off unless code reads pixels.

**API facts** (check the installed version):
- New atlases are Sprite Atlas V2 assets (`.spriteatlasv2`), included in builds and loaded automatically by default (verified on 6000.6).
- When a sprite belongs to several atlases, Unity picks one of them at random at runtime (verified on 6000.6).
- Atlas Padding defaults to 4 pixels between sprites (verified on 6000.6).

## Tilemaps, palettes and rule tiles

**Goal.** Levels built from tiles read as authored places, with correct edges and corners, and collision that matches what the player sees.

**Build.**
1. Make a Grid with one Tilemap per layer (background, ground, foreground decoration), and paint from the Tile Palette window.
2. Use Rule Tiles from Tilemap Extras for ground that picks its own edges and corners: Create > 2D > Tiles > Rule Tile, a Default Sprite, and Tiling Rules on a 3 × 3 neighbor grid, with random outputs for variety.
3. Build levels from data when an agent authors them: write tiles from a level grid with `Tilemap.SetTiles`, so the level can be regenerated and diffed.
4. Collide with a Tilemap Collider 2D and a Composite Collider 2D on the same GameObject, with a Static Rigidbody 2D beside them and the tilemap collider's Composite Operation set to Merge, so neighboring tiles become one smooth shape.
5. Choose the composite's Geometry Type: Outlines for edge colliders, Polygons when overlap queries need solid shapes.

**Watch for.** Thin lines between tiles come from atlas bleeding, bilinear filtering or sub-pixel camera positions. Separate box colliders per tile catch characters on the seams.

**Critic checks.** PASS when no seams or gap lines show between tiles, platform edges and corners use the right pieces, and characters stand exactly on the visible tops of tiles. FAIL signs: lines flickering between tiles; inner corners drawn as outer ones; a character snagging on a flat floor or floating above it.

**API facts** (check the installed version):
- A Rule Tile is created with Create > 2D > Tiles > Rule Tile and matches neighbors through a 3 × 3 rule grid (verified on 6000.6).
- The Tilemap Collider 2D's Composite Operation (None, Merge, Intersect, Difference, Flip) combines tile shapes through a Composite Collider 2D on the same GameObject (verified on 6000.6).
- The Composite Collider 2D's Geometry Type produces Outlines (hollow, like an edge collider) or Polygons (solid) (verified on 6000.6).
- The Tilemap Collider 2D updates its shapes in `LateUpdate`, batching tile changes together (verified on 6000.6).

## Sorting

**Goal.** Sprites overlap in a readable, intended order, including characters walking in front of and behind props.

**Build.**
1. Define Sorting Layers once (Background, Ground, Characters, Foreground, Effects), and use Order in Layer within each.
2. Put a Sorting Group on multi-sprite characters, so their parts sort as one.
3. For top-down and isometric games, set the 2D Renderer's Transparency Sort Mode to Custom Axis with a Y of 1, so objects higher on screen draw behind, and put sprite pivots at the feet.

**Critic checks.** PASS when characters pass in front of and behind props correctly, and no multi-part sprite shows parts of other sprites between its pieces. FAIL signs: a character drawn over a tree it stands behind; arms slicing through another character.

**API facts** (check the installed version):
- The 2D Renderer's Transparency Sort Mode is Default, Perspective, Orthographic or Custom Axis, with a Transparency Sort Axis for the custom case (verified on 6000.6).

## 2D lights and shadows

**Goal.** Light gives the scene mood and depth with one consistent direction, and shadows fall away from their lights.

**Build.**
1. Light ambient with a Global light (one per blend style and sorting layer), then add Spot lights for torches and lamps, Freeform lights for windows and areas, and Sprite lights for shaped glows.
2. Set each light's Target Sorting Layers, so backgrounds and characters can be lit differently; in 6.6, rendering layers can also filter which objects a light affects.
3. Cast shadows with Shadow Caster 2D on occluders, choosing its Casting Source (the sprite, a Collider 2D for tilemaps with composite colliders, a hand-edited shape, or a Sprite Skin for rigged characters), and tune each light's Shadow Strength and Softness.
4. Rank brightness on purpose and keep a dark base, so lights read.

**Watch for.** Sprites on an Unlit material ignore every 2D light. Many overlapping lights and shadow casters add light-texture passes; check the cost on the Web tier.

**Critic checks.** PASS when lights fall off naturally, shadows stretch away from their lights, lit and unlit layers stay readable, and the light direction agrees across the scene. FAIL signs: flat, uniform brightness; shadows toward a light; a character lit by a torch on the far side of a wall.

**API facts** (check the installed version):
- 2D light types are Spot, Sprite, Freeform and Global, and only one Global light is allowed per blend style and sorting layer (verified on 6000.6).
- Shadow Caster 2D takes its shape from the Sprite Renderer, a Collider 2D, a Sprite Skin or an edited shape, and casts onto other objects, itself, or both (verified on 6000.6).
- In 6.6, 2D lights can choose affected objects with rendering layers as well as sorting layers, and GPU-skinned sprites can cast 2D shadows (verified on 6000.6).

## Normal maps for sprites

**Goal.** Flat sprites catch 2D light like relief where the art calls for it, without paying for it everywhere.

**Build.**
1. Import the normal map as Texture Type Normal Map, and a mask map as Default with sRGB off, aligned pixel for pixel with the sprite.
2. Attach them as Secondary Textures in the Sprite Editor, and give packed sprites the same set of secondary textures so the atlas stays dense.
3. Turn on normal-map lighting only on the lights that need it, at the quality the shot needs.

**Watch for.** Normal maps add a depth pre-pass per layer batch at full screen size, a real cost on the Web.

**Critic checks.** PASS when lit relief (cracks, folds, bricks) responds to moving lights and stays consistent with the light's direction. FAIL signs: relief lit from the wrong side; flat sprites under a raking light that the brief says should show texture.

**API facts** (check the installed version):
- Sprite normal and mask maps are Secondary Textures added in the Sprite Editor, and using a normal map costs an extra full-size depth pre-pass per layer batch (verified on 6000.6).

## The pixel-perfect camera

**Goal.** Pixel art stays crisp, evenly sized and stable in motion at any window size.

**Build.**
1. Add URP's Pixel Perfect Camera to the main camera, with Assets Pixels Per Unit equal to the sprites' and Reference Resolution set to the art's native resolution (for example 320 × 180).
2. Choose Grid Snapping: Pixel Snapping to keep sprites on the pixel grid, or Upscale Render Texture to render at the reference resolution and scale up, so rotated sprites and effects keep the same pixel size.
3. Choose Crop Frame (Letterbox, Pillarbox, Windowbox, Stretch Fill, or None) for screens whose aspect differs.
4. With Cinemachine, add the Cinemachine Pixel Perfect extension to each Cinemachine camera, so it and the Pixel Perfect Camera stop fighting over the orthographic size; blends between cameras are briefly not pixel-perfect.

**Watch for.** Sprites rotated or scaled by non-integer amounts break the pixel grid unless Upscale Render Texture is on. Window sizes that aren't whole multiples of the reference resolution can add bars or uneven pixels.

**Critic checks.** PASS when every pixel on screen is the same size and edges stay crisp while the camera pans. FAIL signs: shimmering or crawling edges during camera motion; some pixels doubled; blurry upscaling.

**Start here** (adjust to the goal): a 320 × 180 reference resolution, which scales evenly to 1280 × 720 and 1920 × 1080.

**API facts** (check the installed version):
- The Pixel Perfect Camera's Grid Snapping is Pixel Snapping or Upscale Render Texture, and its Crop Frame is None, Pillarbox, Letterbox, Windowbox or Stretch Fill (verified on 6000.6).
- The `CinemachinePixelPerfect` extension lets Cinemachine cameras and the Pixel Perfect Camera agree on a pixel-perfect orthographic size (verified on 6000.6).

## 2D physics

**Goal.** 2D bodies move, collide and settle reliably at a known rate, with feel that comes from tuning rather than accident.

**Build.**
1. Use Rigidbody 2D (Dynamic for physics-driven bodies, Kinematic for script-moved ones, Static for level geometry) with Box, Circle, Capsule, Polygon, Edge or Composite colliders.
2. Move with `linearVelocity`, `linearVelocityX` and `linearVelocityY`, or forces, in `FixedUpdate`; damp with `linearDamping`. The old `velocity` names are in [foundation.md](foundation.md).
3. Give the player a capsule with a zero-friction Physics Material 2D, so it slides off walls, and use Continuous collision detection and interpolation on fast or camera-followed bodies.
4. Make one-way platforms with a Platform Effector 2D, and conveyor or wind areas with Surface and Area effectors.
5. Keep gravity and the layer collision matrix in the Physics 2D settings, separate from 3D physics; 3D and 2D colliders never touch each other.
6. PhysicsCore2D (new in 6.5, namespace `Unity.U2D.Physics`) is a separate low-level scripting API with its own settings page; games built from Rigidbody 2D and collider components keep using the regular 2D physics.

**Watch for.** Mixing 3D and 2D components on one object, which never collide. Tutorials that call `Rigidbody2D.velocity` hit deprecation messages; the API Updater can rename those calls.

**Critic checks.** PASS when bodies rest flush on surfaces without jitter, fast bodies never pass through walls, and the player slides along walls instead of sticking. FAIL signs: a character sticking to a wall mid-jump; bullets through thin platforms; bodies trembling at rest.

**API facts** (check the installed version):
- Rigidbody 2D has `linearVelocity`, `linearVelocityX`, `linearVelocityY` and `linearDamping` (verified on 6000.6).
- Continuous collision detection on a Rigidbody 2D catches every collision along its path, at a higher cost than Discrete (verified on 6000.6).
- The Physics 2D Simulation Mode runs the step right after `FixedUpdate`, right after `Update`, or from script with `Physics2D.Simulate`; the PhysicsCore 2D settings page covers only the `Unity.U2D.Physics` scripting API (verified on 6000.6).

## 2D animation: sprite swap and bones

**Goal.** Characters animate with anticipation, follow-through and clean timing, their feet stay planted, and outfits or expressions change without new animation.

**Choose.**
- **Frame-by-frame** animation (sprite sheets as Animation clips) for pixel art and small sprites.
- **Skeletal** animation with the 2D Animation package for painted characters: import layers with the PSD Importer, add bones and weights in the Skinning Editor, and deform with Sprite Skin; IK Manager 2D with limb or chain solvers poses arms and legs.
- **Sprite swap** for outfits, expressions and variants: a Sprite Library Asset with categories and labels, a Sprite Library on the character, and a Sprite Resolver on each part.

**Build.**
1. Drive states from an Animator with short transitions ([camera-and-animation.md](camera-and-animation.md)), and match run cycles to ground speed.
2. Key anticipation and squash before jumps and landings, and hold impact frames briefly.
3. Keep the pivot at the feet, so flipping and sorting stay correct.

**Watch for.** A Sprite Skin deforms correctly only when every bone entry has a transform; Auto Rebind can find them from the Root Bone.

**Critic checks.** PASS when frames show anticipation before jumps and attacks, contact frames on landings, no sliding feet, and swapped parts that line up with the body. FAIL signs: popping between frames; floating or skating feet; a swapped part offset from the rig.

**API facts** (check the installed version):
- Sprite swap uses a Sprite Library Asset, a Sprite Library component and a Sprite Resolver that picks sprites by category and label (verified on 6000.6).
- Sprite Skin deforms a sprite with the bones and weights set in the Skinning Editor (verified on 6000.6).
- 2D Animation 16.0.1, bundled with 6000.6.4f1, poses chains with an IK Manager 2D and its solvers (verified on 6000.6).

## Parallax

**Goal.** Layered backgrounds give depth that matches the camera's motion, without jitter or seams.

**Build.**
1. Split backgrounds into layers by distance (sky, far hills, mid trees, near foliage), each with a parallax factor.
2. Move each layer by the camera's movement times its factor, after the camera has moved for the frame (a late execution order, or a camera-rendering callback), so layers don't lag a frame behind a Cinemachine camera.
3. Repeat looping layers by wrapping tiles that share edges, and snap each layer to the pixel grid in pixel-art games.
4. Tint and soften distant layers toward the sky color, so depth reads in value as well as motion.

**Critic checks.** PASS when walkthrough frames show far layers moving less than near ones, with no seams in looping layers and no jitter against the foreground. FAIL signs: all layers moving together; a seam sliding across the sky; a background shaking while the camera pans.

## 2D game feel

**Goal.** A 2D game feels responsive and alive: every action answers at once, and hits land.

**Build.**
1. Take coyote time, jump buffering, variable jump height and hit-stop from [characters-physics-and-feel.md](characters-physics-and-feel.md).
2. Frame the play space with a Position Composer and a Confiner 2D that keeps the screen edges inside a polygon, and shake with Impulse, turning on the listener's Use 2D Distance ([camera-and-animation.md](camera-and-animation.md)).
3. Layer feedback: squash and stretch, landing dust, a hit flash, a short shake, a sound from a randomized container, and a brief hold on impact frames.
4. Keep death and restart quick, with no loading screen between attempts.

**Critic checks.** PASS when frames after each input show a response within a frame or two, hits show flash, particles and a pose change together, and a restart returns to play quickly. FAIL signs: a jump with no anticipation or landing; a hit with no feedback; a long fade before every retry.

**API facts** (check the installed version):
- Confiner 2D keeps the camera's screen edges inside a 2D polygon, for orthographic and perspective cameras (verified on 6000.6).
- The Impulse Listener's Use 2D Distance ignores the Z axis when measuring distance to a source (verified on 6000.6).

## Symptom → cause

| Symptom | Likely cause | First check |
| --- | --- | --- |
| Sprites ignore 2D lights | Unlit sprite material, or not the 2D Renderer | the sprite material and the renderer asset |
| Pixel art looks blurry | Bilinear filtering or compression on sprites or the atlas | Filter Mode and Compression on both |
| Pixels of different sizes | mixed Pixels Per Unit, or no pixel-perfect camera | each sprite's PPU and the camera's Assets Pixels Per Unit |
| Edges shimmer while the camera pans | no Pixel Snapping, or Cinemachine and the Pixel Perfect Camera fighting over size | Grid Snapping and the Cinemachine Pixel Perfect extension |
| Lines flicker between tiles | atlas bleeding, filtering, or sub-pixel camera positions | atlas padding, Filter Mode and camera snapping |
| Characters snag on flat floors | one collider per tile, with no composite | Composite Operation set to Merge |
| A character draws over props it stands behind | default sorting in a top-down game | Transparency Sort Mode and sprite pivots |
| Parts of a character interleave with others | no Sorting Group on the character | a Sorting Group at the character's root |
| Shadows fall toward the light, or are missing | casting source or light shadow settings | the Shadow Caster 2D source and the light's Shadows |
| A sprite shows parts of its atlas neighbors | not enough padding | the atlas's Padding |
| The Pixel Perfect Camera does nothing | the Built-in-only 2D Pixel Perfect package used | the component's package |
| 2D bodies never collide with others | 3D and 2D physics mixed | each object's Rigidbody and collider types |
| Player sticks to walls mid-jump | friction on the player's collider | the Physics Material 2D |
| Background layers jitter | parallax updated before the camera moved | the parallax script's execution order |
| A rigged sprite doesn't deform | Sprite Skin bone entries without transforms | the Sprite Skin's bone list and Auto Rebind |
